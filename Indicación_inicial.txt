
Actuá como un Senior Frontend Developer, UI/UX Designer y Software Architect especializado en experiencias web modernas, interactivas y de alta calidad.

Quiero desarrollar un producto web profesional, pensado para ser publicado y utilizado por cualquier persona a través de Internet. No debe parecer un ejercicio académico ni una plantilla genérica.

REGLAS GENERALES DEL DESARROLLO:

1. Antes de escribir código, analizá los requerimientos y proponé una arquitectura de carpetas clara y escalable.
2. Utilizá exclusivamente tecnologías frontend. No implementar backend, bases de datos ni autenticación real.
3. Respetá la siguiente base tecnológica:
   - HTML5 semántico.
   - CSS3 y SCSS/Sass.
   - Bootstrap 5.3.
   - JavaScript ES6+.
   - AOS para animaciones al hacer scroll.
   - npm para gestión de dependencias.
4. Incorporá librerías adicionales solamente cuando tengan una utilidad concreta y justificada.
5. Utilizá Sass con partials independientes. No concentrar todos los estilos en un único archivo.
6. El archivo scss/main.scss debe centralizar los imports utilizando @use.
7. El CSS compilado debe generarse en styles/style.css.
8. Configurá package.json con scripts para compilar Sass.
9. Separá la estructura HTML, los estilos, los scripts, los datos y los recursos multimedia.
10. Evitá duplicación de código y utilizá componentes o módulos reutilizables cuando corresponda.
11. Utilizá JavaScript modular mediante ES Modules.
12. La aplicación debe ser completamente responsive: mobile first, tablet y desktop.
13. Implementá navegación funcional, formularios validados y estados visuales claros.
14. Los datos deben ser simulados mediante archivos JSON o estructuras JavaScript locales.
15. Utilizá localStorage cuando sea necesario persistir preferencias o información del usuario.

DISEÑO Y EXPERIENCIA DE USUARIO:

- Diseñá una identidad visual propia.
- Evitá interfaces genéricas de dashboards o templates descargados.
- Utilizá tipografías, colores, espaciados y jerarquías visuales coherentes.
- Incorporá microinteracciones y transiciones suaves.
- Priorizá la legibilidad y la facilidad de navegación.
- Utilizá imágenes optimizadas y recursos visuales de calidad.
- No sacrifiques usabilidad por efectos visuales.
- Respetá prefers-reduced-motion.
- Incorporá estados de carga, vacío, error y éxito cuando correspondan.

SEO Y ACCESIBILIDAD:

- HTML semántico.
- Title y meta description únicos por página.
- Open Graph y metadatos para compartir en redes sociales.
- URLs y navegación comprensibles.
- Imágenes con atributos alt descriptivos.
- Etiquetas ARIA cuando sean necesarias.
- Navegación completa mediante teclado.
- Contraste adecuado.
- Jerarquía correcta de encabezados.
- Sitemap.xml y robots.txt.
- Buenas prácticas de rendimiento y Core Web Vitals.

CALIDAD DEL CÓDIGO:

- Utilizá nombres descriptivos y consistentes.
- Evitá funciones excesivamente extensas.
- No agregues dependencias innecesarias.
- No dejes botones sin funcionalidad.
- No utilices enlaces href="#" como sustituto de funcionalidades.
- No inventes resultados de operaciones que no estén implementadas.
- No utilices información ficticia como si fueran datos reales.
- No dejes código duplicado, incompleto o comentado sin justificación.

FORMA DE TRABAJO:

Primero presentá:
1. Arquitectura propuesta.
2. Estructura de directorios.
3. Dependencias necesarias.
4. Identidad visual.
5. Listado de funcionalidades.
6. Plan de implementación por etapas.

No generes toda la aplicación de golpe. Esperá mi aprobación de la arquitectura y luego avanzá por etapas.

Después de cada etapa:
- Verificá que el código funcione.
- Comprobá que no existan errores de consola.
- Revisá el responsive.
- Indicá los archivos creados o modificados.
- Explicá brevemente qué se implementó.

El resultado final debe ser un producto frontend profesional, funcional, optimizado y listo para publicarse.
